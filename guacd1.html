Apache Guacamole 全球分布式混合架构部署指南

一、 方案介绍

本方案专为拥有全球多地节点（如美西 LA、SJC，欧洲 FRA、DE 等）的网络环境设计。采用 “第三方集成 Web 面板 + 官方原生底层节点” 的混搭微服务架构。

  • 主控中心 (LA)：使用 oznu/guacamole 镜像。提供统一的 Web 交互界面、数据库存储、账号与权限管理。此节点即可顺手接管同城低延迟的所有机器。
  • 远端节点 (FRA/DE等)：使用 guacamole/guacd 原生镜像。仅运行 C 语言转码守护进程，不提供 Web 服务，专职负责本机房内的 RDP/SSH 画面抓取与极速压缩。

二、 核心优势

🚀 极致流畅，告别卡顿

原生协议庞大的流量在远端机房内部 0 延迟消化。跨国公网传输的仅是极其精简的 HTML5 流媒体，代码编写、网页浏览丝滑跟手。

🛡️ 统一管控，凭证不落地

全球所有被控机无需暴露 3389 或 22 端口。团队成员只需访问主控 Web 账号即可直连桌面，无法获取服务器真实密码，阻断勒索病毒爆破。

📉 资源占用极限压缩

远端节点（VPS）无需运行 Tomcat 和 Java，仅运行十几兆内存的 guacd 进程，最大程度节约海外主机宝贵的计算资源。

👥 团队级多租户隔离

原生支持 RBAC（基于角色的访问控制），完美适配项目团队。同一台服务器可分配给多名开发人员，实现工作空间的物理级隔离。

三、 部署命令与防火墙配置

1. 主控中心节点 (LA)

部署包含 Tomcat 与数据库的集成环境，对外提供 Web 访问（端口映射为 8080）。

docker run -d \
  --name guacamole-master \
  --restart always \
  -p 8080:8080 \
  -v /opt/guacamole:/config \
  oznu/guacamole

2. 远端干活节点 (FRA)

部署极简转码组件，暴露 4822 端口供主控跨国调用。

docker run -d \
  --name guacd-edge \
  --restart always \
  -p 4822:4822 \
  guacamole/guacd
安全加固（必做）： 远端节点的 4822 端口严禁直接向全网开放。必须配置防火墙（UFW/iptables），或使用 Tailscale 组网，仅允许 LA 主控的 IP 访问。

四、 反向代理配置 (仅需在主控节点进行)

Guacamole 高度依赖 WebSocket 来传输画面。反代配置不当会导致连接断开或强降级为极度卡顿的 HTTP 轮询。

方案 A：Nginx Proxy Manager (NPM) 图形化配置

  1. 在 Details 选项卡中，填写域名并指向主控容器 8080 端口。
  2. 核心开关：务必勾选 Websockets Support ✅
  3. 在 SSL 选项卡中配置证书并勾选 Force SSL，保存即可。

方案 B：原生 Nginx 核心配置 (片段)

location / {
    proxy_pass http://127.0.0.1:8080/;
    proxy_buffering off;
    proxy_http_version 1.1;
    # 必须携带以下 Upgrade 头以支持 WebSocket
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}

五、 Web 面板连接配置实战 (LA 调用 FRA)

核心逻辑提示： 在 LA 面板填写的“目标主机 IP”，是站在 FRA 节点 guacd 的视角来看的，因此通常填写 127.0.0.1。

RDP 桌面配置

  1. 协议： 选择 RDP
  2. 网络： 主机名填 127.0.0.1，端口填 3389。
  3. 身份验证： 填写 Windows 系统账号密码。安全模式建议选 NLA 并勾选忽略证书。
  4. 代理参数 (guacd)： 主机名填 FRA 的公网/内网 IP，端口填 4822。

SSH 终端配置

  1. 协议： 选择 SSH
  2. 网络： 主机名填 127.0.0.1，端口填 22。
  3. 身份验证： 填写 Linux 的账号密码（或直接粘贴 Private Key 私钥，更安全）。
  4. 代理参数 (guacd)： 主机名填 FRA 的公网/内网 IP，端口填 4822。

六、 团队多用户协作配置 (同一台服务器共享)

为项目开发团队分配环境，合理管控考勤与加班时间的开发进度，可通过底层的账户权限隔离来实现一机多用的目的。

实现逻辑： 操作系统底层新建多个独立用户 -> Guacamole 创建对应数量的连接 -> 将这些连接分别分配给不同的团队成员 Web 账号。
  1. 系统底层准备：
    • Linux端： 直接在系统内通过 useradd 创建多个开发人员的子账号。由于 Linux 天生支持多用户并发 SSH，互不干扰。
    • Windows端： 需要运行 Windows Server，并在系统内创建多个普通用户。Server 版支持多人同时 RDP 远程登录并拥有各自独立的桌面环境。
  2. 创建独立连接： 在 Guacamole 面板，为同一台机器创建多个连接。网络配置完全相同（同 IP 同端口），但 身份验证 (Authentication) 部分分别填写刚创建的不同子账号密码。
  3. 分配 Web 账号： 进入【设置 -> 用户】，为团队成员创建独立的 Web 账号，并在权限列表中，仅勾选分配给他的那一台特定的“专属连接”。

效果：团队成员使用自己的 Web 账号登录后，首页仅显示自己的开发环境。点击进入后，代码与文件均处于物理隔离状态，完美实现多租户管理。
