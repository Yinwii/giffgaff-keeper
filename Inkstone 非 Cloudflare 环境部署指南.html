Inkstone 部署指南

Inkstone 非 Cloudflare 环境部署指南

当面临 Cloudflare 账号限制或需要完全私有化自托管知识库时，本指南提供通过 VPS 容器化本地仿真（全功能生产态） 与 GitHub Pages（纯前端离线体验版） 的完整实操与维护方案。

📊 方案核心特性对比

部署方案 功能完整度 数据存储介质 多设备云同步 访问响应 适用场景
VPS 容器化 (生产预编译态) 100% 全功能 宿主机本地 SQLite / 磁盘 ✅ 完美支持 (WebSocket) ⚡ 毫秒级秒开 个人与团队私有知识库、多端实时同步
GitHub Pages ~50% 离线演示 浏览器 IndexedDB ❌ 不支持 (单机离线) ⚡ 静态秒开 个人单设备写作、静态演示、免服务器
💡 原理提示： Cloudflare 官方开源了底层运行时 workerd 与本地仿真引擎 Miniflare。Inkstone 在 VPS 上通过本地构建期预编译，配合 Vite Preview 模式，实现零延迟秒开、低内存占用、零账号依赖的 100% 本地闭环。

🚀 方案 A：VPS 容器化一键部署（强烈推荐，生产预编译秒开）

通过 SSH 连接进入 VPS 终端后，您可以选择以下任一方式完成目录与配置文件的创建（Debian Glibc 镜像 + 构建期预编译）：

直接在 VPS 终端复制并运行以下整段指令，将自动创建 /opt/inkstone 目录并写入经过生产态优化的 Dockerfile 与 docker-compose.yml：

Terminal Command (生产态秒开版) 
# 1. 创建专用目录并进入
mkdir -p /opt/inkstone && cd /opt/inkstone

# 2. 一键创建生产态 Dockerfile (预编译 CodeMirror/Mermaid 等大包，秒开无卡顿)
cat << 'EOF' > Dockerfile
FROM node:24-slim

WORKDIR /app

RUN apt-get update && \
    apt-get install -y --no-install-recommends git ca-certificates && \
    rm -rf /var/lib/apt/lists/*

RUN git clone https://github.com/Yinwii/inkstone.git . && \
    npm install

RUN npm run build:kv

EXPOSE 8787
VOLUME ["/app/.wrangler/state"]

CMD ["npx", "vite", "preview", "--mode", "kv", "--host", "0.0.0.0", "--port", "8787"]
EOF

# 3. 一键创建 docker-compose.yml
cat << 'EOF' > docker-compose.yml
services:
  inkstone:
    build: .
    container_name: inkstone-server
    restart: unless-stopped
    ports:
      - "48787:8787"
    volumes:
      - ./data:/app/.wrangler/state
    environment:
      - NODE_ENV=production
EOF

# 4. 查看创建结果
ls -la

1. 创建目录：mkdir -p /opt/inkstone && cd /opt/inkstone
2. 新建 Dockerfile：nano Dockerfile，粘贴配置代码后按 Ctrl + O 回车保存，Ctrl + X 退出。
3. 新建 compose：nano docker-compose.yml，粘贴配置代码后同样 Ctrl + O 回车保存，Ctrl + X 退出。

1. 打开宝塔/1Panel的 「文件」 页面，进入 /opt 目录。
2. 点击 「新建目录」，命名为 inkstone 并进入。
3. 分别点击 「新建文件」，创建 Dockerfile 和 docker-compose.yml 并粘贴对应内容保存。

  • 一键启动容器服务

    在 /opt/inkstone 目录下执行：

    Terminal 
    # 构建镜像并启动容器
docker compose build --no-cache
docker compose up -d

# 查看运行日志
docker compose logs -f

    启动成功后，即可在浏览器直接访问：http://<你的VPS公网IP>:48787

  • 数据持久化与自动定时备份

    所有笔记、用户数据、附件均在宿主机 /opt/inkstone/data 目录，添加每日定时备份指令：

    Crontab Backup 
    # 每日凌晨 3:00 自动备份，只保留最近 7 天
(crontab -l 2>/dev/null; echo "0 3 * * * tar -czvf /opt/backup_inkstone_\$(date +\%Y\%m\%d).tar.gz /opt/inkstone/data >/dev/null 2>&1") | crontab -

⚡ 方案 B：VPS 原生环境部署 (Node.js + PM2 / systemd)

适合已安装 Node.js 且不使用 Docker 的服务器环境：

Native Setup & PM2 Start 
# 1. 克隆代码并安装依赖
git clone https://github.com/Yinwii/inkstone.git /opt/inkstone
cd /opt/inkstone
npm install

# 2. 编译生产资源
npm run build:kv

# 3. 使用 PM2 启动生产服务
npm install -g pm2
pm2 start "npx vite preview --mode kv --host 0.0.0.0 --port 48787" --name inkstone
pm2 save && pm2 startup

🔑 初始账号与密码设定说明

💡 Inkstone 没有预设的默认账号或弱密码，采用“所有者自初始化”机制：
  1. 首次访问自动引导：启动服务后，首次通过浏览器打开 http://<你的VPS公网IP>:48787，系统检测到底层数据库为空，会自动展示 「创建所有者账号」 页面（提示：创建你的所有者账号，这一步只会出现一次）。
  2. 账号密码自主设定：
    • 用户名：由你自行输入（例如 admin、owner 或你的昵称）。
    • 密码：由你自行输入（要求至少 8 位字符）。
  3. 成为管理员：提交后该账号自动成为此实例的最高管理员（Owner），后续多设备登录均使用刚才设定的账号密码。

🧠 深度科普：为什么不是每个开源项目都能这样本地部署？

一个开源项目能否成功通过本地 Docker 容器化独立运行，必须经过以下 4 项核心指标 的检验：

核心指标 合格标准 不合格项目的典型表现
① 依赖可闭环 所有依赖包可通过 npm/pip 等公开拉取，无私有或付费 SDK 缺少商业 License 密钥，构建时报 401 错误
② 运行时可模拟 云原生 API（如 Serverless）有官方或开源的本地模拟层 强依赖 AWS DynamoDB / 微信云原生且无本地模拟器
③ 网络可穿透 服务端支持监听 0.0.0.0 且端口可配置 写死只能监听 127.0.0.1 导致容器外无法访问
④ 数据可外挂 数据库文件支持指定目录，能完美持久化在宿主机 Volume 数据保存在容器内部未指定目录，重启升级即丢数据

🔄 后续项目有更新时的升级维护指南

所有笔记与账号数据均存放在 data/ 目录，任何升级操作绝对不会丢失已有笔记与用户数据：

Docker Upgrade Commands 
cd /opt/inkstone

# 1. 备份数据
tar -czvf backup_before_update.tar.gz ./data

# 2. 强制拉取最新代码重新构建镜像
docker compose build --no-cache

# 3. 平滑重启容器
docker compose up -d

# 4. 清理旧镜像
docker image prune -f
Node.js / PM2 Upgrade Commands 
cd /opt/inkstone

# 1. 备份数据
tar -czvf backup_before_update.tar.gz ./data

# 2. 从 GitHub 拉取最新提交
git pull origin main

# 3. 安装新增依赖并重新打包
npm install
npm run build:kv

# 4. 重启 PM2 守护进程 (或 systemctl restart inkstone)
pm2 restart inkstone

1. 打开你的 GitHub Fork 仓库页面。
2. 点击仓库右上角的 「Sync fork」 -> 「Update branch」。
3. GitHub Actions 会自动触发重新编译并部署，2 分钟内自动完成更新。

🌐 Nginx 反向代理与 SSL (含 WebSocket 支持)

若需配置自定义域名与 HTTPS，请务必启用 Upgrade 和 Connection 标头以确保实时多端协同与 WebSocket 正常：

/etc/nginx/conf.d/inkstone.conf 
server {
    listen 80;
    server_name notes.yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name notes.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/notes.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/notes.yourdomain.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:48787;
        proxy_http_version 1.1;

        # WebSocket 协同关键配置
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }
}

📦 方案 C：GitHub Pages 自动化构建（离线 Demo 体验版）

适合免服务器场景，在仓库中建立 GitHub Actions 工作流，自动构建纯前端 Demo 模式（数据存放在客户端 IndexedDB 中）：

.github/workflows/deploy.yml 
name: Deploy Inkstone to GitHub Pages

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: 'pages'
  cancel-in-progress: true

jobs:
  build-and-deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '24'
          cache: 'npm'

      - name: Install dependencies
        run: npm install

      - name: Build Demo Mode
        run: npm run build:demo

      - name: Setup Pages
        uses: actions/configure-pages@v5

      - name: Upload Artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: './dist/demo'

      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
⚠️ 注意： 在 GitHub 仓库设置 Settings -> Pages 中，将 Source 选为 GitHub Actions 即可。
