Monolith 完整部署教程

这是一份针对 Monolith 项目的完整部署说明，重点覆盖：项目结构、环境要求、本地常驻部署（默认：nohup）、systemd 备选方案、4 切 5 的操作、直接使用 5 的操作、后台访问、日志与排障、生产化建议。

一眼看懂： 默认推荐先用 4（nohup） 快速跑通；想长期稳定运行，再切到 5（systemd）。
默认方案 4：nohup 后台常驻 备选方案 5：systemd 常驻服务 4 切 5：从 nohup 切到 systemd 直接用 5：跳过 4 直接 systemd 后台入口与访问地址

部署方案总览

默认推荐

4：nohup 后台常驻

最快跑起来，不占当前终端窗口，适合先验证项目能不能跑。

  • 优点：简单、直接、上手快
  • 缺点：不开机自启，不自动拉起
  • 适合：第一次部署 / 快速试跑
备选方案

5：systemd 常驻服务

更正式的托管方式，适合长期运行。

  • 优点：开机自启、崩了自动拉起
  • 缺点：比 nohup 多一步 service 配置
  • 适合：稳定长期运行
迁移路径

4 切 5

先用 4 跑通，再停掉 4，切换到 5。

  • 关键点：先停 4，再启 5
  • 不要同时运行，避免端口冲突
直接上长期方案

直接使用 5

跳过 4，直接用 systemd 部署。

  • 适合：你一开始就要长期运行
  • 前提：你接受稍复杂一点的配置

1. 项目说明

Monolith 原生是一个 Cloudflare Pages + Cloudflare Workers 架构的博客系统。官方推荐方式并不是传统 Docker 长驻服务，但可以通过 本地开发模式长期后台运行 的方式，在 VPS 上实现可持续访问。

前端
Vite + React，默认端口 5173
后端
Wrangler dev / Hono，默认端口 8787
数据库
本地 D1（Wrangler local）
运行方式
4=nohup；5=systemd

2. 当前服务器部署位置

/root/docker/Monolith

当前已使用的关键文件/目录：

/root/docker/Monolith/client
/root/docker/Monolith/server
/root/docker/Monolith/server/.dev.vars
/root/docker/Monolith/runlogs/server.log
/root/docker/Monolith/runlogs/client.log
/root/docker/Monolith/runlogs/server.pid
/root/docker/Monolith/runlogs/client.pid

3. 环境要求

  • Node.js 18+（推荐更高版本）
  • npm
  • 能够访问外网拉取 npm 包
  • 服务器开放前端访问端口（当前是 5173）
注意：这是本地常驻部署，不是官方 Cloudflare 生产部署方案。

4. 完整部署步骤（默认方案：nohup 后台常驻）

默认路线：如果你只是先把项目跑起来，优先走 4。最省事。

步骤 1：克隆项目

cd /root
git clone https://github.com/one-ea/Monolith docker/Monolith

步骤 2：安装依赖

cd /root/docker/Monolith
npm install

步骤 3：创建本地开发环境变量

cd /root/docker/Monolith/server
cat > .dev.vars <<'EOF'
ADMIN_PASSWORD=admin123456
JWT_SECRET=monolith_local_jwt_secret_2026
EOF

步骤 4：初始化本地数据库

cd /root/docker/Monolith/server
npm run db:migrate:local
npm run db:seed:local

步骤 5：后台启动后端

mkdir -p /root/docker/Monolith/runlogs
cd /root/docker/Monolith/server
nohup npm run dev > /root/docker/Monolith/runlogs/server.log 2>&1 &
echo $! > /root/docker/Monolith/runlogs/server.pid

步骤 6：后台启动前端

cd /root/docker/Monolith/client
nohup npm run dev -- --host 0.0.0.0 > /root/docker/Monolith/runlogs/client.log 2>&1 &
echo $! > /root/docker/Monolith/runlogs/client.pid

步骤 7：验证服务

curl -I http://127.0.0.1:5173
curl -I http://127.0.0.1:8787
重要提示：4 和 5 可以在文件层面共存，但不要同时运行。否则会抢占同一个端口（5173 / 8787）。

5. 备选方案：systemd 常驻服务

适合长期运行：如果你更看重开机自启、自动恢复、标准化托管，就选 5。

5.1 创建后端 service

cat > /etc/systemd/system/monolith-server.service <<'EOF'
[Unit]
Description=Monolith Server (Wrangler Dev)
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/docker/Monolith/server
ExecStart=/usr/bin/npm run dev -- --ip 0.0.0.0 --port 8787
Restart=always
RestartSec=5
Environment=NODE_ENV=development

[Install]
WantedBy=multi-user.target
EOF

5.2 创建前端 service

cat > /etc/systemd/system/monolith-client.service <<'EOF'
[Unit]
Description=Monolith Client (Vite Dev)
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/docker/Monolith/client
ExecStart=/usr/bin/npm run dev -- --host 0.0.0.0 --port 5173
Restart=always
RestartSec=5
Environment=NODE_ENV=development

[Install]
WantedBy=multi-user.target
EOF

5.3 重新加载并启动

systemctl daemon-reload
systemctl enable monolith-server monolith-client
systemctl start monolith-server monolith-client

6. 4 切 5：从 nohup 切换到 systemd

推荐迁移方式：先用 4 跑通，再切到 5。迁移时记住一句话：先停 4，再启 5。

6.1 先停止 4（nohup）

kill $(cat /root/docker/Monolith/runlogs/server.pid) || true
kill $(cat /root/docker/Monolith/runlogs/client.pid) || true

6.2 确认端口释放

ss -lntp | grep -E ':5173|:8787' || true

6.3 按第 5 节创建 systemd service 文件

也就是先执行 5.1 + 5.2。

6.4 启用并启动 5（systemd）

systemctl daemon-reload
systemctl enable monolith-server monolith-client
systemctl start monolith-server monolith-client

6.5 检查状态

systemctl status monolith-server
systemctl status monolith-client

7. 直接使用 5：不走 4，直接 systemd 部署

适合你从一开始就要长期运行：直接用 5，少一次后续迁移。

7.1 克隆项目并安装依赖

cd /root
git clone https://github.com/one-ea/Monolith docker/Monolith
cd /root/docker/Monolith
npm install

7.2 创建环境变量并初始化数据库

cd /root/docker/Monolith/server
cat > .dev.vars <<'EOF'
ADMIN_PASSWORD=admin123456
JWT_SECRET=monolith_local_jwt_secret_2026
EOF
npm run db:migrate:local
npm run db:seed:local

7.3 创建 service 文件

直接执行下面两段命令，分别创建后端和前端的 systemd service：

后端 service（monolith-server.service）

cat > /etc/systemd/system/monolith-server.service <<'EOF'
[Unit]
Description=Monolith Server (Wrangler Dev)
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/docker/Monolith/server
ExecStart=/usr/bin/npm run dev -- --ip 0.0.0.0 --port 8787
Restart=always
RestartSec=5
Environment=NODE_ENV=development

[Install]
WantedBy=multi-user.target
EOF

前端 service（monolith-client.service）

cat > /etc/systemd/system/monolith-client.service <<'EOF'
[Unit]
Description=Monolith Client (Vite Dev)
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/docker/Monolith/client
ExecStart=/usr/bin/npm run dev -- --host 0.0.0.0 --port 5173
Restart=always
RestartSec=5
Environment=NODE_ENV=development

[Install]
WantedBy=multi-user.target
EOF

7.4 启动 systemd 服务

systemctl daemon-reload
systemctl enable monolith-server monolith-client
systemctl start monolith-server monolith-client

7.5 验证

systemctl status monolith-server
systemctl status monolith-client
curl -I http://127.0.0.1:5173
curl -I http://127.0.0.1:8787

9. 日志、PID、停止与重启

查看 nohup 日志

tail -f /root/docker/Monolith/runlogs/server.log
tail -f /root/docker/Monolith/runlogs/client.log

查看 PID

cat /root/docker/Monolith/runlogs/server.pid
cat /root/docker/Monolith/runlogs/client.pid

停止 nohup 服务

kill $(cat /root/docker/Monolith/runlogs/server.pid)
kill $(cat /root/docker/Monolith/runlogs/client.pid)

查看 systemd 日志

journalctl -u monolith-server -f
journalctl -u monolith-client -f

重启 systemd 服务

systemctl restart monolith-server monolith-client

10. 常见问题

Q1：4 和 5 可以共存吗？

配置文件和教程步骤可以共存，但运行中的服务不要共存。因为它们会抢同一组端口。

Q2：什么时候用 4？什么时候用 5？

想快速试跑，用 4。想长期运行、开机自启、自动恢复，用 5。

Q3：如果我已经在跑 4，还能切到 5 吗？

可以，按第 6 节操作：先停 4，再启 5。

11. 生产化建议

  • 长期运行优先用 systemd
  • 用 Nginx / Caddy 反代前端和 API
  • 给前端加域名，例如 blog.example.com
  • 限制后台入口访问来源，增强安全
  • 将默认密码改成强密码
