OpenList 存储挂载与 Root 目录排错全指南

包含 Docker CLI、Docker Compose 部署规范与常见五大高频报错排查

🚀 标准部署配置（支持一键复制）

方案 A：Docker Compose（推荐）

在目录中创建 docker-compose.yml 并粘贴：

docker-compose.yml 
services:
  openlist:
    image: openlistteam/openlist:latest
    container_name: openlist
    restart: unless-stopped
    user: "0:0"
    ports:
      - "5244:5244"
    volumes:
      - /etc/openlist:/opt/openlist/data
      - /:/host
    environment:
      - UMASK=022

方案 B：Docker CLI 命令行运行

Bash 
docker run -d --restart=unless-stopped \
  --name="openlist" \
  --user 0:0 \
  -p 5244:5244 \
  -v /etc/openlist:/opt/openlist/data \
  -v /:/host \
  -e UMASK=022 \
  openlistteam/openlist:latest
⚠️ 安全提醒： 挂载宿主机整机拥有极高管理权限。若只用于浏览/下载、无需增删系统文件，强烈建议将挂载点设为只读模式：- /:/host:ro。

⚙️ OpenList 网页后台参数正确设置

进入后台（端口 5244）→ 存储 → 添加 → 驱动选择 本机存储 (Local)：

配置字段 填写值 核心说明
挂载路径 / 或 /host OpenList 网页端呈现的根目录名称。
根文件夹路径 /host 或 /host/root 切勿填 / 或 /root
必须填写容器内部的挂载位置（即 /host），填 /root 访问的是容器自带的空目录。

🛠️ 常见五大高频问题深度排查

1. 启动失败并无限退出 (v4.1.0+ 报错)

Error: Current user does not have write and/or execute permissions for the ./data directory: /opt/openlist/data
  • 原因：OpenList 4.1.0+ 默认以非 root 用户 (UID 1001) 运行。宿主机 /etc/openlist 由 root 创建，容器内用户无权写入。
  • 方案：在 Docker 运行参数加上 --user 0:0（推荐），或在宿主机执行 chmod -R 777 /etc/openlist。

2. 访问 root 提示 Permission Denied

  • 原因：Linux 系统的 /root 目录默认权限为严格的 700（仅 root 用户可读写）。
  • 方案：启动时指定 root 身份：命令行加入 --user 0:0，或 Compose 中声明 user: "0:0"。

3. 成功进入 root 目录，但里面完全是空的？

  1. 填错了路径：后台“根文件夹路径”写成了 /root（访问的是容器内部空环境），正确应为 /host/root。
  2. 全是隐藏文件：Linux 的 /root 默认主要是 .bashrc、.ssh 等点开头隐藏文件，OpenList 默认策略会将其过滤。可在宿主机终端执行 touch /root/test.txt 验证。
  3. 历史错误缓存：无权访问时的失败状态被缓存，在网页右上角点击 🔄 刷新图标 强制更新。

4. 为什么不能直接将整机挂载到容器根目录 -v /:/ ？

Docker 容器启动依赖基础镜像环境。若直接将外部根目录覆盖容器内部的 /，原容器环境依赖和 OpenList 二进制程序文件会被宿主机直接冲垮，导致容器崩溃无法启动。

5. 查看报错日志时，为什么内容极少且死循环刷屏？

  • 程序未启动即被拦截：错误由镜像自带的 entrypoint.sh 脚本抛出并执行 exit 1，OpenList 主程序根本尚未加载，因此不会生成业务堆栈日志。
  • 死循环重启冲掉日志：容器配置了重启策略，在反复退出与拉起时不断打印退出提示，导致管理脚本在通过 --tail 查看时，历史输出全被大量重复的报错顶出屏幕。
