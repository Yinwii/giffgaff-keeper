🏢 2. 核心架构分工策略

BITSFLOW-DE（总入口与监控）
德国纽伦堡同城节点 (与 Netcup 同城)
网关中枢
  • 同城极低延迟：BITSFLOW 与你的 Netcup 均位于 DE-NUE（纽伦堡），互相反向代理延迟仅 1~3ms。
  • 网关物理解耦：即使后端 Netcup 上的 Halo 或 笔记容器挂了，NPM 依然在线，可返回标准的友好维护页。
  • 维护操作建议： 
    # 1. 彻底删除已经挂掉 6 周的冗余容器
docker rm dufs
# 2. 停止并删除重复的文件管理器（2o 机已有）
docker stop filebrowser && docker rm filebrowser
Netcup-BW25（门户与通信）
高配生产力机器
公网门户
  • Docker-Mailserver 邮箱服务：最高级别安全保护。邮箱 IP 信誉极度脆弱，严禁在此机运行任何爬虫或高频对外请求，防止 IP 进垃圾邮件黑名单。
  • Halo 博客系统：个人对外公开门面。
  • 当前维护项：当前邮件容器呈 unhealthy 状态，需检查自检端口与 SPF/DKIM/DMARC 反向解析（PTR）。
Netcup-2oVPS（私有知识资产）
私有云与个人资产库
私有核心
  • 笔记与写作资产：集中运行 Inkstone-server、Papergrid 或 Memos，这是核心私密资产。
  • 个人导航工作台：运行 Sun-Panel，集成所有内外部服务的直达入口。
  • 私有文件网盘：保留运行良好的 Filebrowser 与 WebDAV，对接本地日常办公。
Netcup-1oVPS（脏活跑批专用）
自动化脚本专用小鸡
风险隔离
  • 青龙面板 (Qinglong)：托管第三方开源脚本库，物理隔离可能存在的恶意扫描与内存泄露。
  • tg-signpulse：将签到通知类机器人从 BW25 迁移至此统一调度。
  • 稳定运行红线：必须开启 2G Swap，限制并发数为 1~2，Cron 定时任务错开整点。

⚡ 4. 桌面环境与高占用进程清理复盘 (SOP)

此前由于后台常驻的 Epiphany 浏览器及 WebKitWebProcess 死循环，导致双核机器 Load Average 飙升至 6.0+。标准清除流程：

# 1. 立即停止并禁用 xrdp 与 lightdm 桌面环境服务
sudo systemctl stop xrdp lightdm
sudo systemctl disable xrdp lightdm

# 2. 强杀残留的所有桌面与 WebKit 渲染进程
sudo pkill -9 -f 'WebKitWebProcess|epiphany|xfce|xfwm4|xrdp|lightdm|Xorg'

# 3. 切换默认系统启动级别为纯命令行模式（multi-user）
sudo systemctl set-default multi-user.target

# 4. 彻底卸载清理桌面组件包并清理废弃依赖包
sudo apt purge -y xrdp xorgxrdp lightdm 'xfce4*' 'xfwm4*' 'xserver-xorg*' epiphany-browser
sudo apt autoremove --purge -y && sudo apt clean

# 5. 低配 1C1G 小鸡（如 Netcup 1o/2o）快速开启 2G Swap 防爆内存
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

🚀 5. 迁移与下线执行计划

  1. 第一阶段：解构 `bits-FRA-SMSM` 并下线
    • 将有价值的 inkstone-server（墨石笔记）、papergrid、sun-panel（导航）迁移至 Netcup-2oVPS。
    • 放弃无用测试容器，在账单后台关闭自动续费，任其到期释放。
  2. 第二阶段：净化 `Netcup-BW25` 独立生产机
    • 将签到类的 tg-signpulse 迁出到 Netcup-1oVPS（与青龙面板集中管理）。
    • 排查修复 mailserver 容器的 unhealthy 状态，确保独立干净的邮局信誉。
  3. 第三阶段：长效测试闭环
    • 利用 本地 PVE-fnOS 或 ColoCrossing 消耗型机器完成所有新镜像调试，固化 docker-compose.yml 后再投产。
