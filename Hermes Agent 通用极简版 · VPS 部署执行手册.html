⭐ 1. 终极推荐方案：Hermes Agent 通用极简版 Docker Compose（零明文 Key）

架构铁律：动静分离，绝不在 YAML 中硬编码付费 API Key！
本方案为官方最推崇的标准生产模板。Compose 仅负责提供最精简的基础设施（Telegram 网关 + 网页后台 + 持久化数据卷 + 资源硬上限）。大模型凭据在上线后通过 9119 网页控制台或向导录入，享受动态热切换、换 Key 永不停机、备份绝不泄密的最高安全性。
通用极简版生产配置文件 (`/root/data/docker/hermes/docker-compose.yml`)
唯一推荐基准 
services:
  hermes:
    image: nousresearch/hermes-agent:latest
    container_name: hermes-agent
    restart: unless-stopped
    ports:
      - "9119:9119"       # Web 管理面板端口 (用于图形化配置模型 Key、查看记忆与自学技能)
    volumes:
      # 持久化存储 Agent 会话记忆 (MEMORY.md)、数据库与已配置的模型凭据
      - /root/data/docker/hermes/data:/opt/data
    environment:
      - TZ=Asia/Shanghai
      - HERMES_DASHBOARD=1                      # 开启 9119 图形化控制台
      
      # ================= 访问与身份凭据 =================
      - TELEGRAM_BOT_TOKEN=你的BotToken           # 向 @BotFather 申请的通信口令
      - TELEGRAM_ALLOWED_USERS=你的TG纯数字ID     # ⚠️安全关键：锁定个人 ID，严防公网盗刷 API 额度

      # 💡 说明：此处完全不写任何 API_KEY 或 BASE_URL！
      # 启动后在 9119 面板或命令行向导中动态录入 AgentRouter / DeepSeek，热生效不重启。
    deploy:
      resources:
        limits:
          cpus: '1.5'          # 最多调用 1.5 核
          memory: 1200M        # 内存硬上限 1.2G，为 2C2G 宿主机留足 800MB 底线

🤖 2. AI Agent 选型对决与 AgentRouter 多场景对接

为什么选择 Hermes Agent 而非 OpenClaw？
选型胜出
对比维度 OpenClaw Hermes Agent (最终选定) 架构决策理由
内存占用 空闲 600M~900M，执行时冲高至 1.5G~3GB+ 守护进程仅 ~250M，整体常驻 600M~900M Node.js 频繁 GC 与内存泄露；Hermes 基于精简 Python + SQLite，极轻量。
配置与维护 繁杂的 openclaw.json，ClawHub 插件生态脆弱 单文件配置，原生具备自学技能机制 (Curator) Hermes“教一次自动写脚本固化”，免去繁琐维护。
功能与场景 企业级多渠道网关 (支持 20+ 通道，多 Agent 协同) 个人全能助理 (Telegram 直连、定时任务、工具调用) 90% 的企业通道功能对个人完全闲置，Hermes 恰到好处。
接入 AgentRouter 平台规范与官方指引
大模型中枢

官方集成参考：https://agentrouter.org/docs/hermes.html (官方文档)

姿势一：9119 网页控制台热配置（OpenAI 协议）

配合上述通用极简 Compose 开箱即用，免写代码：

  1. 启动容器后浏览器访问 http://2o机器IP:9119 进入 Settings -> Model Providers；
  2. 选择 OpenAI Compatible，填入参数：
    • Base URL: https://agentrouter.org/v1 (必须带 /v1)
    • API Key: 粘贴你的 AgentRouter API 密钥
    • Model ID: gpt-5.5/glm-5.2
  3. 点击保存即刻热生效，手机 Telegram 直接对话。
姿势二：挂载 TS 扩展接入 Claude Opus 4.6

适用于对深度思考链有极高要求的场景：

  1. 创建扩展目录：mkdir -p /root/data/docker/hermes/data/extensions；
  2. 保存为 agentrouter.ts： 
    export default function (pi: ExtensionAPI) {
  pi.registerProvider("agentrouter-claude", {
    name: "AgentRouter Claude",
    baseUrl: "https://agentrouter.org", // 严禁加 /v1
    apiKey: "",
    api: "anthropic-messages",
    models: [{ id: "claude-opus-4-6", name: "Claude Opus 4.6", contextWindow: 1000000, maxTokens: 8192 }]
  });
}
  3. 重启容器，Hermes 自动加载扩展，即可调度 Claude Opus。
Telegram 通信与安全白名单核心逻辑：
1. 为什么不需要配 Chat ID 就能聊天？ Hermes 作为 Telegram Bot 采用主动长轮询（Long Polling）机制通信，当你在手机端发消息给它时，Telegram 报文自动携带了你的动态 Chat ID，Bot 原路回复，因此日常对话无需预置 Chat ID；
2. 为什么必须配置 TELEGRAM_ALLOWED_USERS？ Telegram 机器人公网完全公开。不配置白名单，任何陌生人找到你的 Bot 都能跟它对话，肆意盗刷你的大模型 API 余额！搜索官方 @userinfobot 获取本人纯数字 ID 填入锁定；
3. 没配 AI 时 TG 能对话吗？ 机器人会在 Telegram 显示在线，斜杠内置命令（/help, /model）可以响应，但日常聊天会直接报错提示缺少模型凭据。

🌐 5. BitsFlow 核心职能定位：Web 业务反向代理 (NPM)

为什么把 NPM 放在 $7 的 BitsFlow 上做转发？

1. 七层 Web 反向代理（当前实际用途）

  • 统一公网门牌号：所有外部域名全部解析到 BitsFlow 的独立 IPv4，收敛 80/443 端口；
  • 业务流量智能分诊：访客访问 blog.xxx.com 转发至 BW25，访问 notes.xxx.com 转发至 2oVPS；
  • 掩护核心机器真实 IP：外部攻击和扫描只打在 $7 的 BitsFlow 门面上，BW25 邮件机与 2o 数据机处于受保护状态；
  • 同城几乎零损耗：BitsFlow 与 Netcup 均位于德国纽伦堡（DE-NUE），同城转发延迟仅 1~2ms，无感路由。

2. 四层网络端口中转（VPS 圈常见用途）

  • 网络线路跳板：通过 realm 或 gost 工具为国内直连丢包严重的海外小鸡进行网络中转救砖；
  • IPv4 / IPv6 互转：为纯 IPv6（IPv6-Only）廉价机器提供 IPv4 入口穿透；
  • 运维注意：当前优先保证 NPM 稳定运行，不要跑高并发大流量中转把网卡占满。

⚡ 8. 桌面环境与高占用进程清理复盘 (SOP)

此前由于后台常驻的 Epiphany 浏览器及 WebKitWebProcess 死循环，导致双核机器 Load Average 飙升至 6.0+。标准清除流程：

# 1. 立即停止并禁用 xrdp 与 lightdm 桌面环境服务
sudo systemctl stop xrdp lightdm
sudo systemctl disable xrdp lightdm

# 2. 强杀残留的所有桌面与 WebKit 渲染进程
sudo pkill -9 -f 'WebKitWebProcess|epiphany|xfce|xfwm4|xrdp|lightdm|Xorg'

# 3. 切换默认系统启动级别为纯命令行模式（multi-user）
sudo systemctl set-default multi-user.target

# 4. 彻底卸载清理桌面组件包并清理废弃依赖包
sudo apt purge -y xrdp xorgxrdp lightdm 'xfce4*' 'xfwm4*' 'xserver-xorg*' epiphany-browser
sudo apt autoremove --purge -y && sudo apt clean

# 5. 低配小鸡（如 Netcup 1o）快速开启 2G Swap 防爆内存
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
