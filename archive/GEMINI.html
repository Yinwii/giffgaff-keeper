为了提供极致、统一的高端视觉交互体验，应用中所有弹窗和对话反馈必须遵循以下规范： - 全面取缔原生弹窗：除非项目底层逻辑或极端系统环境导致无法实现，否则严禁在页面中直接调用浏览器原生的 alert()、confirm() 以及 prompt() 对话框。 - 高定制对话交互：所有的警告提示、操作二次确认、文本输入捕获必须封装为高度美化、与产品主题契合的 HTML 弹出层组件。 - 去毛玻璃化与实色背景：默认情况下，所有的弹窗、编辑窗禁止使用毛玻璃 (backdrop-filter 等模糊效果)，除非有特殊要求。遮罩层应使用纯黑半透明 (rgba(0,0,0,0.75))，弹窗主体应采用与项目主题色调一致的实色背景（如 var(--bg-primary)）并辅以高级投影。 - 警告与高危操作文字高亮规范：对于涉及清空、删除、清除、重置、物理覆盖等极具高危破坏性操作与后果的确认弹窗（Confirm/Alert），其危险操作字眼、核心动作动词、破坏性后果（如“所有加班预报数据”、“删除员工”、“清除数据”、“清空”、“此操作无法撤销！”）必须强制加红加粗（使用 <span style="color:#ef4444; font-weight:bold;"> 包装渲染）；而关键参数与主体内容（如具体的“日期”、“姓名”、“班次”、“周数”等）则必须使用蓝色加粗（使用 <span style="color:#2563eb; font-weight:bold;"> 包装渲染），以此在视觉上提供强对比度的危险警告，极大降低误操作风险。 - 小圆角控件输入：所有输入框的线条必须统一使用小的圆角样式（如 border-radius: 6px），确保整体风格紧凑、专业。 - 视效动效要求：弹窗弹出时必须带有平滑的微缩放或淡入动画（缩放动作推荐从 scale(0.95) 平滑过渡到 scale(1) 展开）。 - 易用性与退出机制：弹窗的操作按钮必须有舒适的点击响应范围（Padding）。对于常规确认弹窗，按下 Esc 键、点击遮罩暗色背景、或者点击"取消"按钮均须能安全关闭弹窗，确保操作逻辑的自如与安全，绝对严禁强制锁死用户视口。

  • 全局强制适用性：只要在项目或其衍生应用中包含文本、Markdown 或是长文本编辑器的需求，必须提供功能完整丰富、交互流畅的高级定制编辑器，严禁直接暴露或使用简陋无工具栏的 <textarea> 文本域。
  • 全端自适应响应式双轨布局 (Responsive Layout & Sync Scroll)：
    • 编辑器必须具备良好的响应式设计，能够根据显示终端的宽度进行双轨自适应分流：
      • 宽屏终端（PC端）：采用左侧源码编辑、右侧实时解析渲染的双栏联动滚动布局，通过监听两端的 scroll 滚动事件，通过 scrollTop / (scrollHeight - clientHeight) 的比例因子进行联动计算，以规避因两侧内容高度不一致导致的视线脱靶；同时需采用状态锁（如 isSyncing）来安全切断事件环路，防范无线循环触发。
      • 窄屏终端（移动端/轻量侧栏）：双栏必须自动折叠为单栏，并提供显式的 Tab 切换按钮（"源码编辑" / "实时预览"）进行一键平滑视图切换，防止元素挤压变形，确保在小屏幕下也有极佳的录入与核对体验。
  • 丰富功能快捷工具栏 (Rich Toolbar)：
    • 工具栏必须包含并完整覆盖以下一击即中的快捷按钮：
      • 基础排版：加粗（**）、斜体（*）、下划线（<u>）、删除线（~~）、高亮标记（==或<mark>）、一键清除选中格式（正则清洗 Markdown 语法符号）。
      • 标题段落：H1 (#)、H2 (##)、H3 (###)、H4 (####)。

6.1 前置脚手架自检机制 (Pre-Flight Architect Checklist)

强制阻断：每当接收到从零创建一个新项目或大重构的指令时，无论需求多急迫，AI 绝对禁止直接编写业务代码！ 必须首先在后台建立 task.md 并强行输出执行以下【基建三板斧自检】： - [ ] 1. 是否已脱离本地污染，直接编写无 venv 的原生纯净启动脚本？ - [ ] 2. 是否已剥离硬编码，生成并挂载了专属的 .env 单一事实池？ - [ ] 3. 端口是否严格落实了单一数据源规则（即代码内部严禁兜底回退数字）？ 仅当以上三项基建打上 [x] 后，才被授权继续写功能逻辑！

6.2 任务善后与闭环操作

每当接收并完成各类业务需求时，AI 须按照以下步骤闭环： 1. 最高守则联级备份：若在此会话中修改了本全局规范（GEMINI.md），则必须在完成修改后，立即物理覆盖/更新全局备份目录 C:\Users\Wii Yin\.gemini\protocol_backups\ 下的 GEMINI.md 主备份和带时间戳的防灾备份快照文件，同时物理覆盖/更新具体项目根目录下的同名防灾备份快照文件（即项目级 GEMINI.md），这是绝对纪律！ - HTML 镜像双轨同步 (HTML Mirror Sync)：每次更新 GEMINI.md 规范后，必须将其渲染为包含基础排版的 HTML 文件（GEMINI.html），并将此 HTML 文件与 GEMINI.md 遵循相同的"三重覆盖"逻辑，同步更新到全局根目录、全局备份目录以及具体项目的根目录，确保规范始终具备跨端即开即用的原生网页阅读体验。 2. 文档同步更新：维护 task 与 walkthrough 的热态演进。 3. 全局看板覆写：热更新项目 root 根目录的 README.md 全景图鉴。 4. 归档迁入：使用时间戳对 task 与 walkthrough 重命名并迁入 docs/ 目录。 5. 静默清理：清理 docs/ 下多余的（超过 5 份）老旧文件快照副本。 6. 任务简报：最终向用户提供简明扼要的完成报告。
