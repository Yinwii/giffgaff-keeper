* **⚖️ 端口单一数据源机制**：为了杜绝配置偏移，启动脚本内**不允许**将端口号硬编码在回显字符串中。必须通过环境变量或共享参数（如 `.env`）作为 **单一事实来源 (Single Source of Truth)** 实现启动外壳与后端逻辑的强制对齐。
* **💻 Windows 脚本 encoding 编码**：所有 `.bat` 脚本必须确保在 Windows CMD 环境下无乱码且稳定运行。
    - **首选标准**：推荐使用 **ANSI (GBK/936)** 编码保持最高兼容性，可杜绝解析偏移。
    - **极简防御 (The Iron Bat Protocol)**：若环境极度不稳定（如频繁闪退、逻辑解析失败），必须回退至 **极简指令集**（如直接使用 `for /f` 读取 PID），禁用复杂的 `if` 嵌套、延迟变量扩展 (`EnabledDelayedExpansion`)。
    - **❌ 驱动层零中文原则**：在极简模式下，`.bat` 脚本内部严禁出现任何中文字符（包括注释和 `echo`）。所有业务级的中文回显必须下沉至 Python 或其他高级语言逻辑中处理。
    - **强制停留**：脚本末尾必须显式附带 `pause` 或带有超时的回显捕获，隔离运行失败导致的黑窗口"瞬时消失"。

    - **⚙️ systemd 服务管理规范 (systemd Service Protocol)**：当需要作为 systemd 系统服务运行时，必须成对提供以下服务配置与管理脚本：

        2. **服务删除与清理脚本** (`uninstall-service.sh`)：
            - **安全停止与禁用**：执行 `systemctl stop` 停止服务，并执行 `systemctl disable` 取消开机自启。
            - **物理清理**：彻底删除 `/etc/systemd/system/` 下对应的 `.service` 文件，并执行 `systemctl daemon-reload` 和 `systemctl reset-failed` 以清理系统状态。

## 🚀 核心文档生命周期管理

### 1. 必选文档机制 (The Trinity)
无论项目体量大小，AI 在新建或更新项目时必须同步维护以下核心文档：
- `task.md`：记录本次变更拆解的任务列表与执行进度。
- `walkthrough.md`：总结修改点、演示验收方案或功能避坑说明。
- `README.md`：全局热更新项目全景文档（直接在根目录热覆盖最新逻辑）。

### 2. 溯源追踪：时间戳加注规则
为保留迭代痕迹，所有迁入 `docs/` 目录的归档文档必须在文件名中注入 **日期时间戳**：
- **命名标准**：`task_YYYYMMDD_HHMMSS.md` / `walkthrough_YYYYMMDD_HHMMSS.md`。

### 3. 多重轮换与保留策略 (Rotate & Keep 5)
为在追求可追溯性的同时防止记录淤积：
- **全局阈值**：同类型文件副本（如 `task_*`）在 `docs/` 下最多保留 **5 份** 最新的快照。
- **清理机制**：当副本数量溢出 5 份时，AI 必须主动且静默地丢弃最古老的版本。

### 4. 🗄️ 数据备份与持久化协议
针对具备数据持久化能力（如 SQLite）的项目，必须建立以下备份机制：
- **存储路径**：数据必须在 `data/data_backup/` 路径下进行带时间戳保存。
- **双轨触发 (Dual Trigger)**：
    - **启动强制备份**：每次应用启动 (Startup) 时先对现有数据库进行快照。
    - **功能联动备份**：管理员点击"导出报表"或"重置数据"等关键路径时，同步触发备份。
- **轮换机制**：备份文件严格执行 **Rotate & Keep 5** 策略，即该路径下永远只保留最新的 5 个物理备份。

### 7. 👁️ 关键组件对比度保障协议 (Contrast Protocol)

- **覆盖层独立性 (Overlay Independence)**：所有覆盖层组件（如 Toast 提示、Modal 弹窗、Loading 加载器）必须具备独立于页面主背景的高对比度设计。

- **阴影权重**：通知组件必须具备更深的投影权重（Box Shadow），以在视觉层级上获得"浮动感"，彻底杜绝与背景混淆。

### 9. 🛡️ UI/UX 隐私与专业度规范 (Privacy & Professionalism)

- **反馈闭环响应**: 任何交互（如复制、搜索匹配、解锁失败）必须具备明确的 UI 反馈（如 Toast 提示、Empty State 提示），严禁出现点击无响应的情况。

### 10. 💎 现代化组件交互规范 (Modern UI Components Protocol)
为确保全线产品的界面表现力达到高定级标准，在涉及到表单交互时必须强制实施以下组件级规范：
- **全局强制适用性**：**只要涉及下拉菜单、选项等需求的，必须严格按照此设计规范来。**
- **摒弃原生下拉框 (Ban Native Select)**：严禁在后台管理或高级配置面板中直接暴露或使用简陋的系统原生 `<select>` 标签。
- **高定下拉交互 (Modern Dropdown Select)**：所有的配置型下拉选单必须自定义为现代化组件（例如 `modern-select` ），且必须强制集成以下视觉元素：
    - **圆角与留白**：必须符合现代 Web 审美的圆角边框及舒适的 Padding 呼吸感。
    - **状态指示圆点 (Status Dot)**：选项前方的状态指示圆点和颜色可以**按需灵活规范是否显示**，并且按业务逻辑用不同颜色加以区分（如 `🟢完全开放` / `🟠条件受限` / `🔴极度敏感`），直观传达选项安全层级与业务暗示。

    - **顺滑的选中反馈**：下拉列表项必须具有明显的悬停背景变色，当前选中激活的项目必须拥有独立的高亮底色纹理。

### 11. 🎨 现代化弹窗与对话框规范 (Modern Dialogs & Modals Protocol)
为了提供极致、统一的高端视觉交互体验，应用中所有弹窗和对话反馈必须遵循以下规范：
- **全面取缔原生弹窗**：除非项目底层逻辑或极端系统环境导致无法实现，否则**严禁**在页面中直接调用浏览器原生的 `alert()`、`confirm()` 以及 `prompt()` 对话框。
- **高定制对话交互**：所有的警告提示、操作二次确认、文本输入捕获必须封装为高度美化、与产品主题契合的 HTML 弹出层组件。
- **去毛玻璃化与实色背景**：默认情况下，所有的弹窗、编辑窗**禁止使用毛玻璃** (`backdrop-filter` 等模糊效果)，除非有特殊要求。遮罩层应使用纯黑半透明 (`rgba(0,0,0,0.75)`)，弹窗主体应采用与项目主题色调一致的实色背景（如 `var(--bg-primary)`）并辅以高级投影。
- **警告与高危操作文字高亮规范**：对于涉及清空、删除、清除、重置、物理覆盖等极具高危破坏性操作与后果的确认弹窗（Confirm/Alert），其**危险操作字眼、核心动作动词、破坏性后果**（如“所有加班预报数据”、“删除员工”、“清除数据”、“清空”、“此操作无法撤销！”）必须强制加红加粗（使用 `<span style="color:#ef4444; font-weight:bold;">` 包装渲染）；而**关键参数与主体内容**（如具体的“日期”、“姓名”、“班次”、“周数”等）则必须使用蓝色加粗（使用 `<span style="color:#2563eb; font-weight:bold;">` 包装渲染），以此在视觉上提供强对比度的危险警告，极大降低误操作风险。
- **小圆角控件输入**：所有输入框的线条必须统一使用小的圆角样式（如 `border-radius: 6px`），确保整体风格紧凑、专业。
- **视效动效要求**：弹窗弹出时必须带有平滑的微缩放或淡入动画（缩放动作推荐从 `scale(0.95)` 平滑过渡到 `scale(1)` 展开）。
- **易用性与退出机制**：弹窗的操作按钮必须有舒适的点击响应范围（Padding）。对于常规确认弹窗，按下 `Esc` 键、点击遮罩暗色背景、或者点击"取消"按钮均须能安全关闭弹窗，确保操作逻辑的自如与安全，绝对严禁强制锁死用户视口。

### 12. ✍️ 现代化编辑器与表情包交互规范 (Modern Editor & Emoji Protocol)
* **全局强制适用性**：只要在项目或其衍生应用中包含文本、Markdown 或是长文本编辑器的需求，必须提供功能完整丰富、交互流畅的高级定制编辑器，严禁直接暴露或使用简陋无工具栏的 `<textarea>` 文本域。
* **全端自适应响应式双轨布局 (Responsive Layout & Sync Scroll)**：
    - 编辑器必须具备良好的响应式设计，能够根据显示终端的宽度进行双轨自适应分流：
        - **宽屏终端（PC端）**：采用左侧源码编辑、右侧实时解析渲染的双栏联动滚动布局，通过监听两端的 `scroll` 滚动事件，通过 `scrollTop / (scrollHeight - clientHeight)` 的比例因子进行联动计算，以规避因两侧内容高度不一致导致的视线脱靶；同时需采用状态锁（如 `isSyncing`）来安全切断事件环路，防范无线循环触发。
        - **窄屏终端（移动端/轻量侧栏）**：双栏必须自动折叠为单栏，并提供显式的 Tab 切换按钮（"源码编辑" / "实时预览"）进行一键平滑视图切换，防止元素挤压变形，确保在小屏幕下也有极佳的录入与核对体验。
* **丰富功能快捷工具栏 (Rich Toolbar)**：
    - 工具栏必须包含并完整覆盖以下一击即中的快捷按钮：
        - 基础排版：加粗（`**`）、斜体（`*`）、下划线（`<u>`）、删除线（`~~`）、高亮标记（`==`或`<mark>`）、一键清除选中格式（正则清洗 Markdown 语法符号）。
        - 标题段落：H1 (`# `)、H2 (`## `)、H3 (`### `)、H4 (`#### `)。
        - 列表引用：无序列表（`- `）、有序列表（`1. `）、任务清单（`- [ ] `）、引用区块（`> `）。
        - 媒体组件：超链接插入（交互式 Prompt 捕获 URL 及显示文本）、图片插入（交互式 Prompt 捕获图片 URL 及 Alt 文本）、标准 Markdown 数据表格（`|---|` 占位，至少3列3行）、物理分割线（`---`）、行内代码（` ` ）、多行代码块（` ``` `）。
* **智能光标定位与焦点重获机制 (Cursor & Focus Management)**：
    - 所有的工具栏标签包裹操作必须通过统一的 `insertAtCursor(startTag, endTag)` 动作执行：当有文本被选中时，在选区两端物理包裹标签，重置选区为包裹内容，并确保输入框立即重新获得焦点（`textarea.focus()`）；若无文本选中，则插入对应默认占位符并将光标自动落入标签内部（如链接文本处），严禁发生操作后焦点丢失。
* **系统内置快捷体验 (Shortcuts & Status Bar)**：
    - 编辑器必须强制监听并干预键盘事件：
        - `Tab` 键拦截：阻止默认的焦点元素轮换，在光标当前位置插入 `4` 个空格的排版缩进。
        - `Ctrl + S` 存盘：拦截浏览器默认的"另存网页"行为，直接绑定系统核心的保存 API。
        - 常见标记快捷键：监听 Ctrl/Cmd + B, I, U, K (链接), L (无序列表), Shift+O (有序列表) 等。
        - 状态监控：编辑区底部必须展示行数、列数定位信息（如 `行 1, 列 1`），以及实时解析的字节数/字数。
* **附加物理辅助功能 (Clipboard & Clean Actions)**：
    - 编辑器底部或操作区必须常驻提供 `[复制全文]` 与 `[一键清空]` 辅助按钮：
        - **一键清空**：清除标题及编辑区的所有内容，并自动将编辑状态重置为新建模式，必要时加入弹窗二次确认。
        - **复制全文**：一键将编辑器内容复制到系统剪贴板，且必须严格遵循最高规范中的 `Deployment Compatibility Protocol`（双轨 Fallback 复制机制），确保即使在非安全上下文（纯内网 IP 直连）环境下也能 100% 复制穿透。

### 13. 🔑 现代化登录交互与表单尺寸规范 (Modern Login & Form Dimensions Protocol)
* **大尺寸留白 (Generous Dimensions)**：登录界面的输入栏及主操作按钮必须摒弃原生过于矮小紧凑的尺寸。输入栏高度建议维持在 `48px` 左右，登录按钮高度也应匹配放大至 `48px~50px`，配合适当加大字体，确保界面的高级感与点击操作的极度舒适。
* **密码显隐核对机制 (Password Toggle Protocol)**：任何涉及密码输入的栏位，必须强制在输入框右侧内嵌一个"小眼睛"（如 `fa-eye` / `fa-eye-slash`）的图标切换按钮。点击时能平滑切换 `type="password"` 与 `type="text"`，以方便输入时核对明文，极大降低密码输错率。

### 14. 🎛️ 系统全局配置与控制中心规范 (Global System Settings & Control Center Protocol)
为确保系统的高度可控性与安全隔离，所有业务系统必须标配**[系统全局设置]**管理员控制面板：
* **视觉与交互基准强控**：必须提供全局默认主题（亮/暗模式）及首次登入默认路由的下拉选单。这些选单必须严格遵循 `10. 现代化组件交互规范` 中的高定 `modern-select` 渲染，严禁使用原生下拉框。
* **物理级安全隔离控制**：
    - **注册通道熔断机制**：必须提供一键开关（Switch），控制外部系统登录页面的"自主注册"按钮展示。当关闭时，前端必须物理隐藏注册入口，并出具"系统封闭期"等友好提示。
    - **强密码策略约束**：需预留强制复杂密码（长度、大小写、特型符号）的安全门控开关，为后续扩展提供支持。
* **全局广播公告 (System Banner)**：
    - 必须提供置顶跑马灯/提示横幅的配置输入区。
    - **格式限定与防注入准则**：默认情况下，出于防御 XSS 攻击及保持轻量级的考量，跑马灯公告仅支持**纯文本 (Plain Text)**渲染，不支持自定义字体、字号或颜色。如业务后期确有强烈的富文本视觉需求，必须通过引入标准 Markdown 解析器或安全净化的富文本插件进行严格转义渲染，严禁直接 `v-html` 或 `innerHTML` 灌入裸 HTML。

### 15. ☑️ 现代化复选框与批量操作浮窗规范 (Modern Checkbox & Batch Toolbar Protocol)
* **摒弃原生复选框 (Ban Native Checkbox)**：严禁在数据表或表单中直接使用无样式的 `<input type="checkbox">`。所有涉及单选、多选、全选的框体必须封装为带有玻璃态视效的高定组件（如 `.modern-checkbox-wrapper`）。
* **视觉与动效基准 (Visual & Animation Baseline)**：
    - **常态**：呈现为带有细微玻璃透光感 (`rgba(255,255,255,0.05)`) 和柔和边框 (`1.5px solid rgba(255,255,255,0.2)`) 的小圆角方块（如 `18x18px`，`border-radius: 4px`）。
    - **选中态 (Checked)**：底色及边框必须立即填充为品牌主色调（`var(--accent)`），并散发同色系的辉光阴影 (`box-shadow`)。
    - **对勾动效 (Checkmark Popup)**：内部的对勾必须使用纯 CSS 伪元素绘制，且在选中时必须带有平滑的缩放弹出动画 (`animation: checkmarkPopup 0.2s forwards`，从 `scale(0.5)` 到 `scale(1)`)，增强操作爽感。
* **双模适配 (Dual-Mode Adaptation)**：复选框必须完美兼容亮色模式 (`.light-mode`)，在亮色下底色应为纯白，边框为灰蓝 (`#cbd5e1`)，选中时填充为主视觉蓝 (`#3b82f6`) 且产生浅色辉光。
* **批量操作浮窗 (Batch Toolbar)**：
    - **隐现机制**：当无选中项时，浮窗必须彻底隐藏 (`display: none`) 以释放视觉空间。
    - **滑出动效**：当选中任意一项时，操作浮窗必须以带有下拉渐显动画 (`animation: fadeInDown 0.3s ease forwards`) 的形式平滑滑出，严禁生硬出现。
    - **UI 布局**：浮窗应采用玻璃卡片样式 (`.batch-toolbar`)，内部采用深色透明带内描边的微晶视觉。左侧展示"已选择 N 项"（N 使用等宽字体高亮强调），紧跟批量操作动作按钮（如带有小图标的批量启用/禁用/删除）。所有高危批量动作（如删除）必须强制弹窗二次确认，并从逻辑上阻断对特权账户（如 `admin`）的误操作。

### 16. 🗂️ 现代数据容器与页面导航规范 (Data & Navigation Protocol)
* **单页多面板分流 (Tab Navigation)**：对于功能承载较多的单页面应用（SPA）模块，必须摒弃全页堆砌的粗暴做法。强制要求将子功能（如"列表"、"日志"、"配置"）拆分为无刷新的 Tabs。Tab 切换时应带有平滑的下划线追踪或颜色高亮微动效。
* **沉浸式数据表 (Glass Table)**：废除原生带硬边框的 `<table>` 样式。数据繁重的场景必须应用 `.glass-table` 或同等规格的高定视觉体系：消除内外硬边框，使用柔和的底部边线区分行，带有 `hover` 行高亮反馈。同时，长表格必须确保表头（`thead`）处于粘性冻结状态（`sticky`），防止滚动迷失。

### 17. 🪄 极致微交互与反馈体系 (Micro-Interactions & Input Protocol)
* **功能按钮原子化 (Button Anatomy)**：所有触发实质性业务流的操作按钮（非超链接），必须采用带有透光质感的派生按钮（如 `.btn-glass primary / secondary` 等）。**严禁使用光秃秃的纯文本按钮**，按钮文案的左侧必须强制标配与其动作语意高度吻合的 FontAwesome 实体图标（如 `<i class="fa-solid fa-check"></i> 保存`）。
* **绝对弹窗关闭按钮 (Absolute Modal Close)**：对于任何弹窗、悬浮层，除了底部的"取消"按钮外，必须在其容器的**右上角绝对定位 (Absolute Top-Right)** 一个纯视觉的 `[ X ]` 关闭图标（`.btn-close-icon`）。严禁因使用原生控件等借口遗漏该关闭组件，避免用户视觉焦点的无谓下移。
* **无抖动实时输入过滤 (Debounced Search)**：所有涉及到列表数据检索的搜索框，必须具备 `Debounce`（防抖）监听机制，实现边输入边过滤的丝滑体验，彻底废除"点击按钮才搜索"的滞后操作。
* **输入框尾部动作清除 (Trailing Clear Icon)**：具备搜索或重点输入的栏位，其右侧尾部必须内嵌一个"一键清除"（`X`）或相关辅助操作（如密码可见性切换）的小图标组件，且点击后必须让焦点回跳至输入框内。

### 18. 📦 前端依赖库双模管理规范 (Frontend Dependency Dual-Mode Protocol)
为确保应用在**外网 (Internet)** 与**局域网 (Intranet/LAN)** 两种环境下均可正常运行，所有前端静态依赖库必须遵循以下双模共存规范：
* **本地化原则 (Local First)**：所有 HTML 模板中引用的第三方 CSS 和 JS 库（包括但不限于 TailwindCSS、Chart.js、Font Awesome、Flatpickr、Quill、SortableJS 等），必须优先使用本地静态资源路径 `{{ url_for('static', filename='libs/xxx') }}`。
* **CDN 注释备用 (CDN Commented Fallback)**：每个本地库引用行的紧邻位置，必须以 HTML 注释形式保留对应的 CDN 原始地址。CDN 链接行必须显式标注 `CDN 备用` 前缀，以便运维人员在切换部署模式时快速激活。
* **字体回退 (Font Fallback)**：禁止在 CSS 中通过 `@import url('fonts.googleapis.com/...')` 直拉远程字体。必须注释掉该类引用，并在 `font-family` 中提供完整的系统原生字体栈（如 `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, ...`）作为兜底。
* **缺失库下载机制**：当发现本地 `static/libs/` 目录缺少某个依赖库文件时，必须通过 `Invoke-WebRequest`（或 `wget`/`curl`）从原始 CDN 地址下载至本地对应路径，确保本地快照与 CDN 版本一致。
* **标准引用示例**：
  ```html
  <!-- ====== 依赖库（局域网模式：本地优先，CDN 已注释） ====== -->
  <!-- 本地 Chart.js -->
  <script src="{{ url_for('static', filename='libs/chart.js') }}"></script>
  <!-- CDN 备用: <script src="https://cdnjs.cloudflare.com/ajax/libs/Chart.js/3.9.1/chart.min.js"></script> -->
  <!-- 本地 FontAwesome -->
  <link rel="stylesheet" href="{{ url_for('static', filename='libs/all.min.css') }}">
  <!-- CDN 备用: <link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.4.0/css/all.min.css"> -->
  ```
* **库存目录登记**：项目 `README.md` 的"技术栈"章节必须登记 `static/libs/` 下的完整依赖清单及对应版本号，便于审计和更新。

* **模式切换操作步骤 (Mode Switching Procedure)**：
  双模共存的核心是"本地行与 CDN 行互为注释镜像"——任何时候只激活其中一组，另一组以注释形态保留备用。切换时遵循以下规则：

  **方式一：CDN 模式 → 局域网模式**（注释 CDN，激活本地）
  ```
  操作：取消注释本地行 → 注释 CDN 行
  结果：本地 url_for() 生效，CDN 被 <!-- --> 包裹
  ```

  **方式二：局域网模式 → CDN 模式**（注释本地，激活 CDN）
  ```
  操作：取消注释 CDN 行 → 注释本地行
  结果：CDN 直链生效，本地 url_for() 被 <!-- --> 包裹
  ```

  **切换示例对比**（以 Chart.js 为例）：
  ```html
  <!-- ===== 局域网模式（默认） ===== -->
  <!-- 本地 Chart.js -->
  <script src="{{ url_for('static', filename='libs/chart.js') }}"></script>
  <!-- CDN 备用: <script src="https://cdnjs.cloudflare.com/ajax/libs/Chart.js/3.9.1/chart.min.js"></script> -->

  <!-- ===== CDN 模式（切换后） ===== -->
  <!-- 本地 Chart.js -->
  <!-- <script src="{{ url_for('static', filename='libs/chart.js') }}"></script> -->
  <!-- CDN 已启用 -->
  <script src="https://cdnjs.cloudflare.com/ajax/libs/Chart.js/3.9.1/chart.min.js"></script>
  ```
  注意：切换 `CDN 备用:` → `CDN 已启用` 注释前缀以清晰标注当前激活模式。

### 19. 🎨 界面设计美化与悬浮反馈规范 (Aesthetics & Hover Feedback Protocol)
* **CSS 纯网格背景重置与隔离 (Pure CSS Grid Reset & Isolation)**：
    - **实现准则**：网格线背景必须完全基于 CSS 线性渐变（`linear-gradient`）在样式表层级中实现，杜绝使用任何图片资源。
    - **重置清除铁律**：当在 JavaScript 中需要动态切换、清空或移除背景图时，**绝对禁止直接将其内联样式设为 `'none'`**。必须重置为空字符串（`element.style.backgroundImage = ''`），让样式表层级（`.bg-grid-mode` 类）重新接管，从而防范行内样式强制覆盖 class 定义导致网格线无法显现的隐藏 Bug。
    - **颜色深度控制**：亮暗色主题下的网格线条必须极致淡雅和谐。亮色模式下使用微弱透明灰 `rgba(0, 0, 0, 0.12)` 或更淡；暗色模式下使用柔和透明白 `rgba(255, 255, 255, 0.08)` 或更淡。
* **高对比度悬停反馈与文字反白规范 (Hover Visual Feedback & Contrast Protocol)**：
    - **主操作及核心激活按钮**：在鼠标悬停（hover）或点击时，必须完全填充为该按钮对应的品牌/主题实色底色，且**必须通过 `!important` 强制将字色反白为纯白色 (`color: white !important`)**。严禁在 hover 状态下只填充背景而维持原来前景色，避免产生字色与背景底色同化、模棱两可或无法辨识的恶劣体验。
    - **清空/删除/关闭等高危与警示操作按钮**：

        - 悬浮 (hover) 时必须立即瞬间**完全填充为大红色实色底色**，文字**强制反白为纯白色 (`white !important`)**。
        - **字符排阻规则**：对于关闭按钮，严禁直接使用红色的 Emoji ❌，以防在鲜红色背景上由于色调重合导致看不清叉号。必须采用标准的 HTML 文本乘号字符（`×` 或 `&times;`），并适当将字号放大（如 `16px`）且加粗，利用 CSS 字体颜色实现完美反白。
    - **次要及辅助操作按钮**：在 hover 时建议使用温和的同色系低饱和度半透明背景底色（亮色下 `12%` - `16%` 左右，暗色下 `20%` - `24%` 左右），在保证文字可读性的同时，提供平滑细腻的交互响应。
* **浮动悬浮 Toast 提示规范 (Floating Toast Alerts Protocol)**：
    - **多主题独立高对比度**：Toast 提示横幅必须具备完全解耦于页面主卡片底色的独立“深色/高强色”高对比度设计。
    - **视效三维感**：Toast 组件必须配置更深的投影权重（Box Shadow）以散发柔和的发光阴影，在视觉层级上获得“浮动感”，彻底防止在复杂图文背景下与主卡片混淆。
    - **平顺渐显动画**：显示和隐藏必须配置 CSS 平滑过渡淡入淡出动画，严禁生硬隐现。
### 20. 🛡️ 单文件应用双模数据安全引擎规范 (Dual-Mode Data Security Engine Protocol)
* **强制安全提醒与选择权交付**：当开发纯前端的本地离线应用、或单文件 HTML (Single-file HTML) 且涉及数据留存（如 `localStorage`、`IndexedDB` 等）时，**必须在页面右上方等显眼位置部署“数据持久化 ☁️”与“阅后即焚 👻”的双模状态切换开关**。
* **阅后即焚零痕迹机制 (Volatile Mode)**：若用户开启或默认处于“阅后即焚”模式，所有前端产生的数据仅在当前会话的 RAM 内存中流转。任何情况下的页面刷新 (F5) 操作、以及离开或跨页面的读取操作完成后，都必须**第一时间物理清空**相关 LocalStorage 缓存记录，确保他人接手设备后绝对零痕迹。
* **高感知状态滑窗 (Persistent State Toast)**：应用每次打开或刷新时，必须在页面加载完毕后延迟（约 800ms）触发一个底部的滑动弹窗 (Toast)，显式且直白地告知用户当前所处模式（如：“当前为阅后即焚模式，刷新即清空数据”），并且在用户手动点击切换开关时，同步实现立刻保存至硬盘缓存或立刻彻底销毁硬盘缓存的热重载闭环。
### 21. 💡 纯原生去黑框全局智能美化 Tooltip 引擎规范 (Global Intelligent Tooltip Protocol)

* **高定悬浮气泡视效与指示箭头 (Visual & Arrow Customization)**：动态创建并渲染一个置于顶层（如 `body` 末尾）的唯一 `#global-tooltip` 浮框。必须赋予其深空亚克力玻璃质感（`backdrop-filter` + 半透明背景），柔和的小圆角，以及平滑的淡入上浮动画。**同时，气泡必须支持绘制指向按钮的尖角指示箭头，且气泡是否带箭头必须作为一个选择项交由用户自定义修改。**

    - **极简默认**：在不提供额外参数时，系统底层算法自动且聪明地继承当前主题（亮色深空，暗色纯白）。
    - **极客覆盖**：对于特定业务按钮，引擎必须对外暴露 `data-tooltip-bg` 与 `data-tooltip-color` 两个独立的 HTML 属性接口。
    - **强解耦设计**：背景色与文字色强制拆分，以赋能开发者在配置浅色背景时，自由设置深色文字保证高对比度，兼顾灵活性与体验安全感。

### 25. ⚖️ 知情权与选择权交付义务 (Duty to Inform & Options Protocol)
* **系统默认方案的主动告知**：凡涉及本规范中具有极强用户个性化偏好属性的设计（例如：Tooltip 气泡是否带箭头、代码框暗黑底色的色值调整、悬浮导航栏是默认收缩还是常态展开等），AI 在完成编码及交付方案时，**必须绝对尽到主动告知的义务**。
* **定制方案的引导指引**：AI 必须在任务汇报或界面引导中，向用户明确阐述：“当前的默认方案是如何设计的（Why）”，并且**必须手把手地给出透明的修改路径指引（How）**（例如：“若您需要取消气泡的箭头，只需移除 HTML 标签中的 `data-arrow="true"` 属性”）。坚决消除前端配置黑盒，将对体验的最终裁定权和掌控权完整无损地移交用户。

### 26. 📖 长文档大纲实时追踪规范 (ScrollSpy TOC Protocol)
* **侧边空白区高亮追踪 (Side-Gutter ScrollSpy)**：对于包含丰富层级标题的长篇幅文档或工具页，必须在页面侧边的空白区域（Side Gutter）独立渲染一份常驻的静态大纲导航栏。**具体部署在左侧还是右侧，需根据实际的项目场景与整体排版需求灵活决定，左右皆可。** 随着用户的向下滚动阅读，该导航栏必须实时侦测追踪当前所处正文的模块位置，并对正在阅读的标题节点进行醒目高亮（如彩色指示条或字体加粗提亮），同时支持点击标题平滑跳跃至对应模块。
* **响应式防遮挡隐匿 (Responsive Occlusion Prevention)**：为坚守“绝不遮挡正文内容”的底线，此侧边大纲栏**必须且仅能在宽屏设备（如 PC 端宽屏）上展示**。系统必须侦测屏幕宽度，在较窄的屏幕或手机端自动静默隐藏该侧栏（窄屏用户将统一通过右下角悬浮工具栏中的 TOC 功能作为替代），确保任何终端都能自动适配出最纯净沉浸的阅读区。
